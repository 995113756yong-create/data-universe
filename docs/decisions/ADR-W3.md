# ADR-W3：异常告警、AI 提问与回放模式

## 1. 告警放在独立 Flink 作业，读 agg.minute 而不是 raw
- **决定**：新作业 `data-universe-w3-alerts`（`30_alerts_ddl.sql` / `31_alerts_pipeline.sql`），维基激增读 `agg.minute`，地震读 `raw.usgs`。
- **原因**：不动 W1/W2 作业拓扑，savepoint 都能恢复；分钟聚合已经是检测需要的粒度，不用再开窗口。
- **代价**：维基告警比分钟窗口晚 1~2 分钟（W1 关窗 + 本作业 30 秒 watermark）。可接受。

## 2. 检测算法：滚动 z-score + 泊松下限
- 每个地区用过去 30 分钟（有数据的分钟）做基线，剔除当前值；标准差下限取 `max(std, sqrt(mean), 1)`。
- 计数近似泊松分布，方差约等于均值；平稳的小地区样本方差可能接近 0，不设下限会把 +3 条误报成 z=10。
- 再加绝对增量 ≥ 10 条，过滤小地区的相对波动。
- **没做**：季节性（日内周期）基线。30 分钟窗口对日内缓慢变化不敏感，作品集场景够用；需要时可换成同时段历史基线。

## 3. 告警口径用两套实现互相对账
- `scripts/verify_w3.py` 用 ClickHouse 窗口函数把同一规则独立重算一遍，与 Flink 产出比 Jaccard ≥ 0.9。
- 阈值在 Flink SQL、verify 脚本、contracts.md 三处出现，契约测试检查一致，防止只改一处。

## 4. AI 提问：工具调用 + 两道防线
- 用 OpenAI 兼容的 Chat Completions + function calling（`run_sql`、`final_answer`），只依赖 httpx，换 DeepSeek / 通义 / Kimi 只改环境变量。
- **第一道**：sqlglot 解析成语法树，只允许单条 SELECT、白名单三张表、禁表函数 / 危险函数 / SETTINGS / FORMAT / INTO，自动补 LIMIT。解析失败一律拒绝。
- **第二道**：ClickHouse 账号 `du_ai`，账号级只读、执行时间和结果行数有上限、只授予三张表的 SELECT。即使守卫有漏洞，也写不了数据、读不到别的表。
- 地球高亮由模型给出地区名或坐标，网关校验范围并把地区名映射到中心点；模型给的非法坐标直接丢弃。
- 成本保护：每 IP 每分钟 5 次、全站每天 300 次、并发 3。
- **没做**：流式输出（SSE）。回答一般 3~10 秒，先用加载状态，体验不够再加。

## 5. 回放：静态文件 + 前端虚拟时钟
- **决定**：导出脚本把一段时间的数据按分钟切成 gzip JSON，前端用 `DecompressionStream` 解压，按虚拟时钟喂给和实时模式完全相同的渲染路径。
- **原因**：作品集需要一个面试官点开就能看的链接，不能要求对方部署 Kafka / Flink。静态文件能放 GitHub Pages，零成本。
- 引入全局 `clock`：引擎着色器时间、航位推算、面板「几分钟前」都从 clock 取时间，回放倍速 / 暂停 / 拖动因此对所有图层自然生效，无需给每个图层写回放逻辑。
- 体积控制：维基每分钟最多 1200 条；航班按 icao24 哈希抽 40% 的飞机、每架每 2 分钟一个位置（航位推算补中间）；60 分钟约 10~20MB。
- AI 在回放里不可实时调用（静态站点没有后端，也不能暴露密钥），导出时把预置问题的真实回答录进 manifest。
